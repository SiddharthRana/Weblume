# What is Largest Contentful Paint, and how do you improve it?

**Largest Contentful Paint (LCP)** measures how long it takes for the biggest piece of content in the visible part of a page (usually a hero image, video poster or large heading) to finish rendering. It's one of Google's three [Core Web Vitals](https://web.dev/articles/vitals).

## What's a good score?

Google suggests aiming for an LCP of **2.5 seconds or less** for most visits. Between 2.5 s and 4 s "needs improvement", and anything slower is considered poor.

## Why it matters

LCP is a good proxy for "when does this page look ready?". If visitors stare at a blank or half-loaded screen, many of them leave, especially on mobile connections.

## Common causes of a slow LCP

1. **Large, uncompressed images.** A 3 MB hero photo takes a long time on mobile data.
2. **Slow server response.** If the HTML itself arrives late, everything else waits.
3. **Render-blocking CSS and JavaScript** in the `<head>` that must load before anything is drawn.
4. **Lazy-loading the hero image**, which tells the browser to wait before fetching the most important image.

## How to improve it

- Compress images and serve modern formats like **WebP** or **AVIF**, at the size they're displayed.
- Don't lazy-load the main image above the fold; consider `fetchpriority="high"` on it.
- Use a CDN or caching so the HTML arrives quickly.
- Defer non-essential scripts and inline only the critical CSS.

## A note on lab vs. field data

Tools like Lighthouse measure LCP in a **lab**: a simulated device and network. Real visitors ("field data") may see faster or slower results. Lab results are great for spotting problems and checking fixes; they're not a promise of what every visitor experiences.
